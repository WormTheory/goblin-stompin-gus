# Menus, saves and online

Saves, options, the debug menu, the Dev tab, the Testing Environment, and online co-op. These notes were CLAUDE.md's; search `src/js` for the names in them. Keep them up to date with the code, with targeted edits.

- **Saves:** smashed blocks are kept once, per chunk, in `chunkEdits`: a `Map` from the block's place in the chunk (`li(lx,y,lz)`) to what's there now, with `v` counting its changes (`world/places.js`: `editAt`, `editPut`, `editDel`, `editsEach`, `editsDrop`; `addEdit` is still the way in for anything that changes a block for good). About 32 bytes a block; the old list per chunk plus the `edits` table keyed by "x,y,z" was 176. `edits` is still there as a stand-in that reads and writes the same store through text (`edits['x,y,z']`, `in`, `delete`, `Object.keys`), for the tests: don't use it in anything that runs often. `node --expose-gc tools/tests/savemeas.js` measures memory a block and the time a save takes. They go in the save packed chunk by chunk (`ed2`, `editsPacked`, `editsUnpack`), about 3 characters each, with each chunk's string reused until it changes; old saves with `edits` still load. `save()` hands the world (`saveObj`) to `worldPut` (`ui/saves.js`): into localStorage while it fits, and once it doesn't (about 5 MB a site, shared with `/test/`, `/hotfix/` and the old versions), the `ed2` goes in IndexedDB and localStorage keeps the rest with an `ed2db` stamp; `load()` sees the stamp, `worldLoadBig` reads the blocks back just after the page loads and rebuilds the chunks already made (`WB.pending` holds saving off until then). The Testing Environment parks a big city in IndexedDB the same way. A failed save says so on screen; the pause menu's Save now (`#saveNow`) saves at once and says whether it worked. `worldPut` runs one save at a time (`WB_Q`), so an older one can't finish last, and `worldLoadBig` takes the blocks IndexedDB holds even under another stamp. `tools/ui/savetest.js` round-trips both forms.
- **The game as it was left (`ui/play-save.js`):** beside the world, under `PLAY_KEY` (one of `SV_KEYS`, so save files carry it), per seed: `score`, `kills`, `playTime`, This rampage's `RAMP` (its sets as arrays), the clock and weather (`clockState`/`clockApply` in `net/net-sync.js`, the same fields `netClock` sends guests) and each active seat's part (`playOf`: health, stamina, a goblin's weapons, ammo and piles, and the vehicle it's in, `playVeh`: car of any `VEH` kind or police, tank, helicopter, Mobile Gear, balloon, plane on the ground; trains, subways, boats, ships, deck weapons and a carrier's jets are skipped). `playSave` runs with `savePos` (every 2 s, pagehide, hidden, `svFlush`), never in the Testing Environment or on a guest; `savePos` saves the ground under a vehicle being driven. `playLoad` (after `load()`) puts back the whole game's part, freezing for winter; `playPlayer` a seat's, from `boot` for player one and `activateP2` for player two, the vehicle made again by `playVehMake` (flying ones on the ground under them, an airborne plane not at all) and entered in the same seat (`R.with`: in with the other player). Dead when saved comes back at full health. New city calls `playReset`. Suite `playsave` (node playsave.js [cases]).
- **Browser save / Local save (`ui/saves.js`, the title menu's `#saveSw`):** the game always plays from localStorage, the working copy (`SV_KEYS`: the world, position, obituary, map, parked city). Local save (File System Access API, Chromium on a computer only: `SV.can`, `SV.why`) also writes it to a file (`svTick`: after each save and every 10 s if anything changed; `svData` takes the world live). Files' handles are kept in IndexedDB (`gsg-saves`, store `files`); the browser save is put aside there (`kv` 'browser') while a file's in use. Switching (`svUseLocal`, `svUseBrowser`) swaps the working copy and reloads. On a new visit the browser asks again for permission on the first click or key (`svConnect`), and a file newer than the working copy wins (`svSync`). Any browser can export the working copy as a save file (`svExport`, a download) and, without Local save, import one (`svImportPick` asks first in `#saveAsk`, then `svImport`); `svPersist` asks for persistent storage on Save now, Export or Import. The Local saves card pops out beside the menu (`ui/title-pop.js`, `titlePop`: Play online and New city's confirm do too, so the title menu never scrolls).
- **Version and updates (`ui/update-check.js`):** `tools/build.py` fills in `GAME_VER` (the newest `## Version X` in the patch notes) and `GAME_BUILD` (a hash of the built page) and writes both to `game/version.json`. Served over http(s), the game fetches that file uncached; a different build shows `#updBtn`, which saves and reloads at `?u=<build>`. The pause menu's seed line (`seedLine`) starts with the version.
- **Sound & picture options (`ui/av-options.js`):** Sound volume is a master gain every sound goes through (`sndDest()`, never `audio.destination` directly; `setSndVol`, localStorage `goblin-stompin-gus-volume`), Brightness a CSS `filter:brightness()` on `#world` (`brightApply`, `goblin-stompin-gus-brightness`), both for every player in split screen. Hide blood (`BLOOD_OFF`, `goblin-stompin-gus-noblood`) stops `blood`/`splat` and hides the pools under the dead.
- **Split-screen pause menus (`ui/input.js`):** in co-op Start pauses just your own half (`pausePlayer`, the `.ppause` panel); its Pause menu button (pad Y) opens the whole menu as that player's (`pause(p)`, `menuBy`, `menuSeat`). Player two's (`menuP2()`) hides Game options, the Dev and Testing Environment tabs, and the `.p1only` parts of the Game tab and Character tab (via `.pause.seat2`); `readInputs` hands the menu only its owner's controller, and the debug menu's Select only player one's. `#menuWho` names whose menu it is. `tools/ui/coopmenu.js` checks it all with two pretend controllers.
- **Players' inputs and player two's window (`ui/seats.js`):** the Controls screen's Players section (`#seatRows`, `seatsRender`, lit by `seatsSeen`) gives the keyboard and mouse and each controller to a seat: `INMAP` (localStorage `goblin-stompin-gus-inputs`; `auto` is the old rule), read by `padSeats` (readInputs' `S1`/`S2`, every controller of a seat applied) and `kbP()` (whose the keyboard is; only player two's while both play here). The keyboard and mouse handlers are named (`onKeyDown`, `onMouseMove`, `onCanvasDown`...) and drive `kbP()`; the mouse is captured on `kbCanvas()`, let go with `unlockMouse()`. Player 2 screen (`W2.mode`, `goblin-stompin-gus-screen2`): Second window opens an empty page (`w2Open`, placed full screen on another monitor through `getScreenDetails` where allowed) that `w2Setup` writes into: the styles copied, P2's HUD (`P2.ui.view`) moved in, and a second `WebGLRenderer` (`W2.r`; made while lent the window's `WebGL2RenderingContext`, since three.js tells WebGL2 by `instanceof`) drawing the same scene (`renderView(p,x,y,w,h,R)`, from `w2Render`; `split==='win'`). Merged far chunks keep their arrays while it's open (`regDrop`). Controllers are read from both windows, the fresher of each (`w2Pads`). `tools/ui/seatshot.js` (after `build_3d.py`) checks it with real three.js.
- **Debug menu:** the quick menu's rows and sections are in `DBG_SECS` (column, title, rows). It's the only home of the debug switches (Game options keeps just the one allowing it, which also shows the Dev tab); its Show / hide tab (`DT.tab`) keeps the rows hidden from the first tab in `DBG_HIDE`. Its Rendering switches only change the picture: props by hiding `PROP_L`/`PROP_G`, fixtures by hiding `FIX_BAR`/`FIX_GLOW`/`FIX_COL` and the sign, signal and billboard groups, and caves, sewers and subways by drawing each chunk from `gfxArr`, a copy with what `gfxRec` says those features wrote filled back in with earth. Its Vehicles rows (Testing Environment only) pick a kind (`DT.veh`, a dropdown like Weather's, `DBG_DD`) and spawn one parked ahead (`tenvSpawnOne`, the panel's list from `tenvVehKinds`). It works outside the Testing Environment too: `TS.dbg` lets the spawns run, `spGround` finds the ground near the player rather than the flat floor, `tenvRoom` checks the footprint is level, and the `tenvArmy`/`tenvPlanes`/`tenvMechs` venues are always kept. Its World section's Time of day slider (`tod` row, `todHour`/`setTodHour`) sets the clock to an hour, 00:00 to 23:00 (`tod` 0 is 06:00, as `hourNow`); Pause time of day (`DT.todStop`, `setTodStop`) stops `updateSky` moving `tod`, and Pause weather (`DT.wxStop`, `setWxStop`) stops `updateWeather` picking new weather, keeping its time left in `DT.wxLeft`. Both are the host's online (`netClock`/`netClockSet`). Its Overlays are the FPS counter, the Sound list and the Info pane (`DT.info`, `infoTick` in `render/daynight.js`: the time of day, weather, moon and where you are, under the clock; the card beside the clock, `#clockTxt`, has only the day and season). Its Interface switches (`UI_PARTS`: a CSS selector per part of the display, hidden through one style sheet) add a row and an Options box each from that table. None of these are saved. The Sound list overlay (`sndNote`, drawn by `sndTick`) names each sound from `sfx(name,...)` around it, or else from the function that made it (`SND_FN` puts those into words); a new sound worth telling apart from its neighbours wants an `sfx` round it. Suite `gfxhide` checks them and the menu's navigation.
- **Profiler (`ui/profiler.js`, the debug menu's Overlays, `DT.prof`, localStorage `goblin-stompin-gus-prof`; hidden in Show / hide to begin with, through `DBG_NEW`, which hides rows added since a hide list was saved):** `safe()` times every name it runs while it's on (`PROF_ON`, a `var` so `safe` can read it before the file runs; `safeT`), each name's own time only (`PROF_CH` takes a timed call inside another off the outer one), and `profWrap` times what isn't in a `safe` of its own (`genChunk` 'gen', `buildChunk` 'meshing', `blkFill` 'lighting', `regionTick`, `renderView` 'render'); `profEvWrap` notes events (`collapseBuilding`, `bigBlast`, `foeBoom`, `explodeCar0`, `airCrash`, `shipBreak`, `crush` of radius 4 or more, chunks made) shown on the graph and against a spike. `PROF_OF` puts each name in a system (`PROF_CATS`); a new `safe` name wants a place there. `profBegin` (top of `frame`) closes the frame before, `profEnd` before each `requestAnimationFrame`. While on, `renderer.info.autoReset` is off so draw calls cover every view, the top line's GPU / wait is the frame's time less the CPU's (the graph's grey), and `EXT_disjoint_timer_query_webgl2`, where there is one, adds the graphics card's own time. Suite `proft`; `tools/ui/profshot.js` a real screenshot.
- **Map markers (`ui/pause-map.js`):** each player's own `p.mark` (`markOf`, `toggleMark`; localStorage `goblin-stompin-gus-marks`, per seed, by seat), set on the Map tab by a click or tap that doesn't drag (`mapClick`, held back 260 ms so a double click still re-centres) or pad Y at the crosshair drawn in the middle; whoever's menu it is sets theirs (`mapOwner`). Drawn by `drawPin` on the map (everyone's) and on that player's own minimap (an arrow and the distance on the rim when it's off). Suite `marks`. The Map tab draws its blocks once into cached tiles (`mapTilesDraw`, `mapTileBuild`: blocks and ruins in separate tiles, at half-octave zoom steps, thrown away when a block in one is first explored, `mapTileStale`) and draws only names, markers and players fresh; a highlighted legend entry is still drawn block by block (`drawMapBlocks`). Ask for a redraw with `mapDraw()` (once a frame), not `renderMap()`. A tile also keeps every legend entry's pieces (`T.hb`, ruins `T.hr`), so pointing at an entry redraws only those (`hlOn`); `tools/ui/maphl.js` times it.
- **This rampage (`ui/rampage.js`):** the pause menu's stats card: goblins slain (`kills`), score, best combo, vehicles destroyed (`RAMP.cars`: every kind in `VEHICLE_KINDS` with `rampage`, all of them, counted by `vehDamage`, `explodeCar0` for cars, `trainHit` once per train car, `shipSink` once per ship), buildings demolished (`rampBldg`, from `collapseBuilding`: each building key once, not by accident) and settlements razed (`rampRazeTick`, from the frame's `dest` update: a place whose `setDestroyed` reaches 1, not counting one already in ruins the first time it's worked out). Reset by `rampReset`, sent to guests in `m.sc`. The HUD's own card, bottom right, is `wreckHud` ("Settlement razed"). Suite `rampt`.
- **Dev tab:** `DEV_ABIL`, `DEV_SCRIPT`, sandbox `SBX`, Structures previewer (`ST`, `stBuildList` — built lazily because `TEST_GROUPS` is defined later).
  The moves preview has a character picker (`DEVP.char`, `devSetChar`, kept in this browser): Gus and Gertie run the same recording (`devSimulate(key,ch)` only dresses the spare hippo differently), Gnash runs the moves in `DEV_GNASH` as a goblin (`DT.gob` on, `gobDims`, `gobMove`) and is drawn on a goblin model posed by `gobBodyPose`, the same pose the others see in co-op. Each model is a figure (`devFig`: its parts, recorded frame by frame, and its rig) in `DEVP.figs`. Gnash's moves have no settings or custom hitboxes here: his pane is frame data (`devRenderGnash`).
  The Enemies section (`ui/dev-foes.js`, `DEVF`) plays each kind in `DEV_FOE_KINDS` through each animation in `DEV_FOE_ANIM` (`devFoSim` records it). It doesn't run the real AI: each step repeats the sums the enemy code does (the chase in `enemies/routes.js`, `civAI`, `cultCalm`/`cultCast`, `guardCalm`/`foeRanged`, `gobMoveStep`), and reads its numbers from `FOES`, `CULT_CAST` and `FB_SPEED`. So a new table value shows up by itself, but a change to one of those poses or timings wants the same change in `DEV_FOE_ANIM`, and a new enemy kind outside `FOES` an entry in `DEV_FOE_KINDS` (every `FOES` kind is listed from the table by itself). Suite `devtest` records every kind and animation.
  The previewer meshes the structure's blocks itself (`stMeshes`), but its dressing (lamps, signals, signs, benches and bins, props inside, doors, shop signs, landmarks, rides, animals, boats) is the game's own: `viewers()` adds stand-ins spread over the box (`ST.view`, `stViewers`) to the players every refresh loop goes round, `stDress` runs those refreshes, and `stDrawDeco` draws just that dressing from the game's scene (`stDecoSet`), cut to the box with clipping planes. So a new kind of dressing shows up there by itself if its refresh loops over `viewers()` and its models are in `stDecoSet`. Fly mode (`stFlySet`, `ST.fly`) is a noclip camera whose position is one more viewer, so furniture loads round it floor by floor.
- **Testing Environment (title screen):** an empty, flat world (`TENV`, saved with the world; null in a normal city). Only the plan's blocks inside spawned boxes (`TENV.boxes`, in plots; `tenvShow(px,pz)`) are generated (`genChunk` returns `flatChunk` elsewhere) or dressed: every refresh that loops over plots near `viewers()` skips the rest, and traffic, crowds, services, trains and pull-overs don't spawn at all. Spawning a structure searches the plan ring by ring with the Structures previewer's `stMatch` (`tenvTick`), and builds it on the nearest clear ground in front of Gus (`tenvSpot`, `tenvPlace`, `tenvRebuild`): a box keeps where it came from in the plan (`sx,sz`) and where it's built (`ax,az`; an old save without `sx` stays put). Inside a moved box and the ring of plots round it, the plan's lookups answer as at the source with their positions moved across (`trInstall` wraps them, only in the Testing Environment; only the outermost call is moved, `TR.d`; moved copies kept per box in `TR.c`), and its chunks are the source's own, made raw (`trChunk`, with `collapses` keys translated). A new plan lookup that dressing calls with a place needs adding to `trInstall` too: `tools/tests/relocmp.sh` (or `relo.js` per kind and `relocmp.js`) builds each kind in place and moved and compares blocks, meshes, props, doors, signs and staff. Its panel (`#testPanel`) is its own menu tab, `tabTest`, right of Game: `tpShow` shows its button only while `TENV` is set, and `showTab` passes over any tab whose button is hidden. Enemies come from `tenvFoe`, cars from `tenvVeh`, tanks and helicopters from `tenvMil` (a base of their own, the `tenvArmy` venue), parked planes from `tenvPlane` (an airport of their own, the `tenvPlanes` venue, flagged `tenv` so `updateTenvPlanes` runs instead of the timetable); Reset world (`tenvReset`) starts a fresh empty one. Entering parks your city under `goblin-stompin-gus-city-parked` and leaving restores it (`tenvEnter`/`tenvLeave`). A new kind of dressing or spawner that loops over plots needs a `tenvShow` check too. Suite `tenv` checks it; `tools/ui/tenvshot.js` takes real screenshots.
- **Online co-op (`net/`, full write-up in `docs/multiplayer.md`):** (the host's smashed blocks go at most `NET_EBUDGET` a snapshot, the rest in the next ones) host-authoritative peer to peer, up to four players (`NET_SEATS`; seats past two made when taken). The host runs the game with a guest's seat driven by its controls (`p.net`, `netHostInputs`); a guest builds the host's world from its save (kept in sessionStorage, `netWorldText` in `load()`, then a reload), sends its controls (`netSendInput`) and draws snapshots (`netSendSnap`/`netCommit`/`netGuestFrame`) `NET.dly` behind (at least `NET_DELAY`, more on a jittery connection, on its own smoothed clock `NET.rt`, carrying places on briefly if a snapshot is late), with the host's goblins and cars as mirrors in `NETM` and venue joints pinned (`netVenues`). Effects reach a guest by wrapping the functions that make them (`netFx`), blocks through `addEdit`; on a guest, damage, `crush`, `setRaw` and `addEdit` do nothing unless the host sent them (`NET_APPLY`). A guest moves its own hippo at once (`NETP`, `netPredStep`) and is eased back (`netPredCheck`); the host rewinds goblins for a guest's attacks (`netRewind`). Transports: Trystero (`NET_TRYSTERO`, loaded on use; TURN hook `NET_TURN`), a BroadcastChannel for two tabs (`netLoopback`), the tests' own via `NET.makeTr`. Open games (`net/net-lobby.js`): with no server, browsers on the Play online panel and listed hosts share one more room, `NET_LOBBY`, where hosts send `ad`s (code, host, players) that the panel lists; picking one joins by its code; "Private game" (`LOBBY.priv`) stays out of it. `netOn()`/`netHost()`/`netGuest()` say what's going on; offline none of it runs. A new effect function worth seeing on a guest wants wrapping with `netFx`; a new thing that changes blocks should go through `addEdit`. Ships online: a guest makes its own copy of each of the host's ships in the same pocket slot (`netShips`/`netShipSet`, `S.net`), so everything aboard is placed by the host's pocket coordinates as it is; what's near a guest is measured out in the world (`netNear`), and the camera's yaw is sent as it is in the world (`netFrameYaw`); the ship's entry also carries its deck weapons (aim, health, wrecked, rounds), where it's broken (`S.brks`, replayed on the guest's copy by `netShipBreaks`, the wreck in the host's slot) and a wreck's tilt, furniture knocked over aboard is an event `sk` plus world bits `sprop`, and `dv` ends with the ship, deck weapon and bridge view; suite `netship`. Suite `net` (no lobby there: its `makeTr` refuses `NET_LOBBY`); `tools/ui/netshot.js` two real tabs (`P2P=1` through the internet), `tools/ui/lobbyshot.js` the Open games list in four tabs.
- **Online chat and voice (`net/net-chat.js`, `net/net-voice.js`):** Enter opens a chat line (`CHAT`, `chatOpen`; while it or a controller's quick list, `chatPad`, is up, `readInputs` zeroes player one's controls); the host cleans, rate-limits and passes on every line (`chatFromGuest`, `chatPost`), shown only through `textContent`. Voice (`VC`) is off until switched on in Options, and must stay free until then: no `getUserMedia`, AudioContext or tracks; on, the microphone goes over Trystero's own connections (`NET.tr.av`) to whoever the host's `vr` list says is on (`vcSync`), push to talk is the `talk` action. Its Options switches (`#vcSub`, shown only while voice is on): My voice (`VC.talk`; the microphone goes through a gain node, `VC.gain`/`VC.micVol`, and `VC.out` is what's sent) and Others' voice (`VC.hear`, told to the host as `hr` in `vo`, listed in `vr`: nobody sends to a player not hearing), each with a volume up to 200% on its row (`.vcrow`), Push to talk above them. Others' voice plays through a gain node per player (`vcOut`: the audio element's kept, silent, while the AudioContext runs; until then the element plays it, at up to 100%); `tools/ui/vcvol.js` checks the layout, the gain and the controller. Suite `chat` (pretend microphone and connection: counts that nothing's made with voice off); `tools/ui/chatshot.js` chats between two real tabs.
