# Goblin Stompin' Gus — notes for Claude

A voxel action game that plays from one self-contained HTML file: **`game/index.html`** (~1.7 MB, ~19,000 lines).
It loads three.js r128 from cdnjs; everything else (world generation, meshing, physics, AI, audio, UI) is inline.
Open the file in a browser to play. The source it's built from is in **`src/`**.

## Source layout
- **Edit `src/`, never `game/index.html`.** `python tools/build.py` joins the source back into `game/index.html`, which stays committed because it's what gets played and published, so commit it along with your change. The test tools rebuild it for themselves. `python tools/build.py --check` says whether it's up to date.
- `src/page.html` is the page and its menus' markup, `src/style.css` the styles, `src/js/` the game script, by topic: `core/` (setup, blocks, audio, the loop, new city, Testing Environment), `world/` (the plan and terrain, `generate.js` has `genChunk`), `buildings/`, `dressing/` (street furniture, props, doors, signs), `render/`, `destruction/`, `player/`, `enemies/`, `vehicles/`, `venues/`, `ui/`.
- **The files in `src/js` aren't separate modules.** They're joined in the order in `src/js/ORDER.txt`, inside one function, so they share one scope: any file can use anything from any other with no imports, and every top-level name must be unique across all of them. No file runs on its own. Order only matters to code that runs while the page loads, such as a `const` read at the top level before the file declaring it. A new file must be added to `ORDER.txt`, or the build stops and says so.
- A topic can be in more than one file, because the code keeps the order it always ran in (`makeCar` is in `vehicles/cars.js`, but `updateCars` is in `vehicles/traffic-update.js`). Search all of `src/js` for a name, rather than guessing the file.
- **Assets** (`src/assets/`): weapons (models and numbers), their animations (`clips`), gun grips (`grips`, how both hands go on a gun), bodies (goblin hurtboxes), props (`props`, the furniture models: `PROPS=assetPropsAll(ASSETS)`) and street fixtures (`fixtures`: lamp, signal, sign, flag and billboard shapes, `FIXM=assetFixAll(ASSETS)`, drawn by `fixDraw`, with `spots` for the signal head, sign face and ad, `fixSpot`; bunting is still code) and the light vehicles (`vehicles`: their models, read by `lightBuild`; their riders' clips are `clips` of layout `'rider'`, kept raw in `ASSETS.clips` rather than `STRIKES`) are JSON files, one per thing, each kind with an `_order.json` the build checks like `ORDER.txt`. The build puts them all in one `ASSETS` table at the top of the script (a file's `note` is left out), and `core/assets.js` (first in `ORDER.txt`, and loaded by the editor too) turns them into what the game reads: `WEAPONS=assetWeaponsAll(ASSETS)`, `STRIKES=assetClipsAll(ASSETS)`, shapes other than boxes through `assetShape`. **Change weapons and animations there, not in `weapons.js` or `strikes.js`**, by hand or with the editor; `assetCheck` says what's wrong with a file, and `assetFmt` is its layout (the editor saves in it, so a hand edit should keep to it). Suite `assets` checks every file. `node tools/assets/golden.js` compares the tables against the literals they were moved from (commit 9cbf98b; models added since, such as the club's dropped one, are listed as new). A weapon's model is one shared shape, `model.boxes`, and each view (`held`, `view`, `drop`, `stow`, listed in `ASSET_LISTS`) is either that shape placed (`{at:{p,r,k}}`: moved, turned XYZ, scaled) or a version of its own (`{at,own:[boxes]}`, `at` kept for going back); `assetList(model,view)` gives the boxes the game draws, `assetPlace` places a box (or takes the placing off). Every view but held still has its own version as moved (`tools/assets/share_models.js`, which fits each one's `at`: first person always turned the same way, `VIEW_TURN`, and a dropped gun with its grip down). An animation (`clips`) runs u 0 to 2 with a track of keys per channel, `tracks:{arm:[[u,value,ease?],...],...}`, channels named and ordered by its layout (`ASSET_LAYOUTS`); `STRIKES[k]` is that list of tracks, `strikeAt` (and `assetPoseAt` for a file) works out each channel from its own keys. They were whole-pose keys until `tools/assets/split_tracks.js` (which proved every pose the same).
- **The editor** (`tools/editor/`): `python tools/editor/serve.py`, then open http://localhost:8737/tools/editor/ (a desktop browser). Thomas edits props and street fixtures (plain boxes, a prop's `@tint` and `glow`, a fixture's `@pole`/`@lamp` and spots: `buildFlat`, `renderFlatInsp`), weapon models, gun grips (with a toggle to see poses with and without both hands on the gun) (held, first person, dropped, put away: tilted boxes, cylinders, cones, wedges, spheres), animations on a timeline, weapon numbers, weapon hitboxes and goblin hurtboxes, and saves into `src/assets/` through the server (refused if the file changed on disk since it was opened). Its Open game button opens `game/index.html?editor`, and `ui/editor-live.js` takes each edit there as it's made (nothing runs without `?editor`). It's meant to replace the Dev tab one tab at a time (only "Models and animation" so far; the Dev tab is still all there), each Dev tab feature going in the commit its editor tab lands. In the editor a weapon's animations are listed under it (the fields in `WCLIPS`) and picked in its Stats from the clips of the right layout; a view's Make unique / Use the shared model switch it between the two model forms; the timeline has a row of keys per channel (and one of every keyed time, which moves all of them at once), the selection `S.key` (`{j,i}` or `{all:u}`); a drag (gizmo or slider) edits with `edit(f,merge,true)`, which leaves the scene alone till it's let go (rebuilding mid-drag drops the gizmo). Channels are shown by `CH_UI` (a name, a hint, degrees or blocks, a range per layout and channel; `toUI`/`fromUI` convert, the files stay in radians). Dragging a part of the posed figure in an animation sets its channels at the playhead (`poseGrab` picks the channels and the point that follows the mouse, `poseStep` solves for them by damped least squares from the screen, kept in `CH_UI`'s range).
- **The editor's Vehicles tab** (`tools/editor/vehicles.js`): the light vehicles' models (`src/assets/vehicles/`: boxes that tilt and belong to parts, each part's point and what it's inside, the rider's clip, with roles `VEH_ROLES` such as `@paint` and `@blinkL`) edited as they stand, every part at rest, and their riders' animations (clips `rd*`, layout `'rider'`: legL, legR, lean, crank) on the timeline, posed on the vehicle that plays them (`vehRiderRig`, `vehRiderPose`), the legs, lean and cranks draggable. The live game takes both (`liveVeh`, `liveClip`).
- **The editor's Hippo tab** (`tools/editor/hippo.js`): the hippos' moves (`src/assets/moves/`, one file per move: its numbers and custom hitboxes, which used to live in the Dev tab and the browser) and their timed animations (clips `hip*`, layout `'hippo'`). A move is acted out by the game in a hidden frame (`game/index.html?editor`, `hipFrame`, `HIP`) and played back with its hitboxes, crater cells and a frame timeline; Gus and Gertie share every move.
- **Structures (the editor's Structures tab, `tools/editor/sites.js`; game side `world/sites.js`; files `src/assets/sites/`):** a site file is one kind of site (a `stMatch` kind, as the Structures previewer lists them) as built, block by block from `y0` up (`size` [x,y,z], `rows` one run-length string per z, `assetSiteDecode`/`assetSiteEncode`/`assetSiteRow` in `core/assets.js`), plus its `props` (`{m,p,yaw,tint}`), `people` (`staff`, `civilian`, `goblin`, or any `FOES` kind) and `cars` (`{k,p,yaw}`, a `VEH` kind), points in blocks from the lot's corner, y absolute. It's captured from the hidden game (`liveSiteCapture` in `ui/editor-live.js`: the plan's blocks raw, nothing smashed, with the furniture every floor would get, a compound's people and `parkSpots0`'s cars) and edited in the tab (tools Select/Add/Remove/Paint/Pick/Box, a cut-away height, its own row-diff undo `d.sUndo`; blocks drawn from the game's atlas, `liveSiteInfo`). With `on`, `sitesLoad` (`SITES`) makes `siteOf(px,pz)` return an instance for every lot of that kind and size (or turned), choosing among versions by `hash2`, turned `k` quarter turns so its `face` (door side, `siteFace`, 0 -x, 1 +x, 2 -z, 3 +z) matches that lot's (`SITE_ROT` turns ramps, stairs and road lines); `siteStamp` (end of `genChunk`) writes it over the plan's blocks, `siteIn` keeps the plan's furniture, doors and brand signs out of the lot, `sitePropsAdd` adds its own (keys `st:`), `parkSpots` (wrapping `parkSpots0`) its cars, and the `siteppl` venue (`refreshSitePpl`, `updateSitePpl`) its people: enemies hold their posts till roused within `rouse` (16), staff and townsfolk stand at their spots. `SAVE_KEY` takes `assetSiteSig`, so a world with sites on is a world of its own. Not yet: the far rings (`farBox`) still draw the plan's building, buildings-destroyed counts and goblin routes use the plan's buildings, landmarks and non-brand signs, the militia's crewed vehicles, and very big sites (an airport) make big files. Suite `sitet` (`KINDS=a,b` to narrow it).
- **Patch notes** live in `src/patch-notes.md`, newest update first (`## ` per update, `### ` per section, `- ` bullets; `build.py` says which bits of Markdown it understands). The build puts them in the menu's Patch notes tab (`#tabNotes`, with the newest update's heading in the title screen's "What's new" line) and builds `game/patch-notes/index.html` from the template `src/patch-notes.html`, which GitHub Pages serves at `/patch-notes/`. Commit that file with `game/index.html`. When a change is worth telling players about, add it to the top update there, or start a new `## ` update, written for players rather than as a commit message.
- **Old versions** are playable from the Patch notes: an older update headed `## Version X` gets a "Play X" link to `<site>/v/X/`, which the Pages workflow builds from the git tag `vX` (`tools/archive_versions.py`, run on every deploy; it warns about a version with no tag). So when a version is released, tag the commit that was pushed (`git tag v0.2 <commit>`) and push the tag with it. Each old copy gets a script that prefixes its localStorage keys with `gsg-vX:`, so old and current saves and settings never mix, and a badge linking back to the latest.
- If `game/index.html` was changed by hand, the build refuses to overwrite it and says how to carry on. `git diff` skips that file, since its changes are already shown in `src/`; `git diff --text` shows it.

## Branches
- **Work on `test`, never on `main`.** `test` is where new work is committed, and pushing it (`git push origin test`) updates the test link, `/test/` on the website. `main` is the live release: it only moves when Thomas releases, by bringing `test` into `main` and pushing it himself. Don't make other branches or worktrees.
- A fix that has to go live before the rest of `test` is a release decision for Thomas. Such a fix is made on the `hotfix` branch, cut from `main` (never from `test`), and pushing it updates `/hotfix/` on the website for trying it out; Thomas brings it into `main`, then `main` is merged back into `test` (`git checkout test && git merge main`) so nothing's lost. The `hotfix` branch is the one exception to making no other branches.
- **Parallel threads share this folder and its git index, so commit through `tools/safe_commit.py`.** Copy what you'll change out of a known commit (`git archive <base> <paths>`) into a scratch folder, edit and test there, then `python tools/safe_commit.py --base <base> --from <scratch> -m "..." [files]`. It merges your change into the branch as it is now (lines others committed meanwhile stay), rebuilds `game/` when `src/` changed, moves the branch only if nobody else just did, and stops on a conflict or a dropped patch-notes line. Never put a whole-file copy, `git checkout --`, `git restore`, `git stash`, `cp` or `cat >` over `src/patch-notes.md` or `CLAUDE.md` here (others' work is in them), and never `git update-ref` without the old value. A cloud session's patch goes in with `git apply --3way`.
- **Never write `src/patch-notes.md` or `CLAUDE.md` whole in this folder** (an old copy takes out everything committed since): change them with targeted edits, and run `python tools/check_stale.py` before committing (`--fix` merges a stale copy back up to HEAD, keeping its own changes). The pre-commit hook (`git config core.hooksPath tools/hooks`) and `safe_commit.py` refuse while a copy is stale; `ALLOW_NOTES_REMOVAL=1` lets a deliberate removal through.

## Ground rules
- `game/index.html` is the only deliverable: it must stay one file that works when simply opened. The build only joins files, so keep it that way, with no bundler or dependencies.
- Parody of real brands is welcome and part of the humour (names like "Goblin Walmart"). Draw parody logos rather than copying real artwork.
- Comments are plain English, explaining *why*, often in parentheses. Match the existing style.
- **Bump `SAVE_KEY`** (currently `'goblin-city-v96'`) whenever world generation changes, so old saves don't load into a different world.
- Make edits with exact, unique string replacements. Many identifiers repeat, so check for a single match within the file before replacing.
- After every change: run the tests (below) before calling it done.

## Running the tests
The game script is pulled out of the HTML and evaluated in Node with a stub THREE and a fake DOM.
That checks logic: world generation, physics, abilities, AI and menus. It doesn't check the real 3D picture.

```bash
bash tools/run_tests.sh                 # smoke, devtest, walk (rebuilds game/index.html and tools/tests/g.js first)
bash tools/run_tests.sh rollt spk lean  # any named suites from tools/tests/
SEED=7 bash tools/run_tests.sh maptest  # Math.random is seeded from SEED
```

The suites only print measurements and never fail on a wrong result, so compare output against the saved baseline:
```bash
bash tools/baseline.sh                  # rewrites tools/baseline/*.txt with timings masked
git diff tools/baseline                 # shows what a change altered; commit it if the change was intended
```

How a test works (see the first ~40 lines of `tools/tests/dead6.js`, which is the standard header):
- **Loading the game.** `mkg.py` rebuilds `game/index.html`, then copies its main `<script>` (the one after the three.js tag) into `g.js`, so `g.js` is all of `src/js` joined up. Each test reads `g.js` and seeds `Math.random`.
- **Reaching internals.** A regex swaps the closing `requestAnimationFrame(frame);\n})();` for `window.__t={...}`, which exposes the functions that test needs. If you add an internal a test must reach, add it to that test's `window.__t={` list.
- **Stubs.** Next come the stub THREE classes (`class Q{` … up to `const listeners=`), a fake `document`, `localStorage` and gamepads.
- **Driving the game.** `eval(src); const T=window.__t;` then `T.frame(now)` advances the game. `run(seconds)` is already defined in the header, so don't redeclare `run`.
- **New test.** Copy the header from `dead6.js`, adjust the `window.__t` export list, then write the checks.

```bash
cd tools/ui && node uist.js      # also: padnav.js (controller menu nav), uishot*.js (screenshots), uiex.js
```

## Map of the code (search `src/js` for these names)
- **World and terrain:**
  - chunk generation `genChunk`; meshing (`meshes`, `MESHED`)
  - far LOD rings `farJobNear`/`farJobMid`/`farJobFar` via `farBox`; out on the plains, farmland and farm fields as patches and farms' and country sites' buildings come from `farCountry` (a landmark as columns of its real height, `farProfile`); trees there come from the same rules the chunks grow them by (`plainsTree`, `parkTree`, kept per block in `farTreesOf`), woods further off from `farWoods`, ponds and lakes from `farPonds`/`farTownWater`
  - world curve `CURVE_U`, lighting `WORLD_LIGHT`. Any second renderer (e.g. the obituary preview) must zero/whiten these while it renders.
- **Roads:**
  - towns `placeAt`; road spans `axisSpan` (kinds include `'moto'`, `'country'`; `flat` ends)
  - motorway ramps `hwRampAt` / `hwRampCol` / `rampBlocked` / `hwFootNear`; route ends `rtFlat`, `rtRamp`
- **Player:**
  - frame loop `frame`. It substeps when dt > 0.05; presses only count on the first substep, and held state like `inp.chargeHeld` carries across.
  - ability switches are each player's own: `ABIL` (player one, localStorage `goblin-stompin-gus-abilities`) and `ABIL2` (player two, `goblin-stompin-gus-abilities2`, first copied from player one's); an online guest's come as `p.abil`. The moves read `ABIL`, so `updatePlayer` swaps in a player's own set for their step; anything reading a switch outside that step asks `abilOf(p)` (and `stompCap(A)`, `poundCap(A)`, `airJumpsMax(A)` take a set). Move tuning lives in `AB`
  - bite / stomp / pound with charge levels (`stompCap`, `poundCap`)
  - dash / sprint / air dash; `longJump` (with `LJ_GRACE`); roll; blast dash / blast air dash; blast long jump (`blastOff`, `crushBall`)
  - rocket boost (`ROCKET_*`); ground spike (`groundSpikes`, `spikeGround`, `SPIKES`); climb; crash landing; fall-damage immunity
- **Destruction:**
  - `crush(...)` (accepts `{round:R}` for round craters)
  - building collapse lean is worked out from the outer walls alone (`outerWalls`: the first and last structural block along each row and column of the footprint, as built): what's still standing of them on the floor that gave way, against the middle of the whole ring. Stairs, pillars, inside walls and furniture don't count. Snapped to a cardinal direction within 20° (`snapCard`). Suite `falldir` (`SC=none|stairs|east|eastwall`)
  - a place wiped out (`setGone`; `goneAt(px,pz)`, `ptGone(x,z)`) is left desolate: no traffic spawns, parks or drives about there (recycled out of sight), route cars heading for it turn back at the route's end or are recycled unseen and none are sent off towards it, ground highways back out of it, off-ramps into it aren't taken, its stations are dead (`stnDown`), nobody's sent there (`updateServices`), goblins and townsfolk there slip away unseen (`updateGoblins`), and its stadium and zoo aren't brought back. Suite `desolate`
  - water flow (`destruction/water-flow.js`): every block `setRaw` turns to air is noted (`wfNoteRemoved`); the next step (`updateWater`, every `WF_STEP`, host only) starts a breach (`wfBreach`) where water sits on it or beside it, and fills one layer of open blocks a step, no higher than that water's surface, until the space is full, through `setRaw` and `addEdit` (so it's saved and sent to guests). The water it came from stays; a body of water under `WF_BIG` blocks spills no more than it holds (`wfBody`), and `WF_CAP` (20,000 a breach) is only a safety net. Blocks it reaches in a chunk that isn't made (or was let go) wait in the breach's `park` until it is. Suite `waterflow`
- **Buttons on screen:** HUD text names a button as `⟦glyph id⟧` (`btnMark`, `bindGlyph`, `actMark`), and `hudHTML` draws it with the menus' `glyph`. Use these for any new prompt rather than `keyLabel`/`padLabel`.
- **Controls:**
  - `ACTS` / `BINDS` (localStorage `goblin-binds-v1`), `KB_RESERVED`, `PAD_RESERVED`
  - `rebindHTML`, `keyLabel`, `padLabel`
  - controller menu navigation `menuNav` (spatial up/down)
- **Abilities menu (Character screen):** shows the switches of whoever's menu it is (`abilSeat`, `renderAbil`). Rows `#abilList > .ab-row`: a basic move (`.ab-base`) and its upgrade tokens (`.ab-tok`, with a `+1`/`+2` coin) in `.ab-up`; the switches are `role="switch"` buttons, on in full colour and off greyed (no tick boxes), using `data-base`, `data-prev`, `data-excl` (roll ⟷ blastDash). Controller up/down moves between basic moves, left/right along a row (`menuNav`). `tools/ui/abilshot.js` checks each player's own switches and takes screenshots.
- **Props:** furniture made of small boxes rather than whole blocks, in proportion to the goblins (about 1.4 tall): models in `PROPS` (from `src/assets/props/`, `propUnfight` run on each), placed by `hospProps`, drawn by `refreshProps` as instanced boxes near the player, knocked down by `knockProps`. Hospitals are laid out by hand; everywhere else `furnProps` reads what `furnRaw` says stands there, and `furnTurns` decides which of those blocks become props (shelves, fridges, sofas, beds, plants, small tables, lone screens). Restaurants (`restProps`), shops and stores (`shopRoom`), malls (`mallProps`), houses (`homeRoom`), flats (`aptFloor`), workplaces (`workRoom`) , public buildings (`civicRoom`) and venues and workplaces such as cinemas and factories (`venueRoom`) are laid out by hand from a shared set of models. Pavement and park benches and litter bins are props too (`streetFurn`, drawn by `refreshProps` out to 96 blocks rather than 34, and listed in `activeFix` so traffic hits them); taller street objects are fixtures (`drawFix`). Goblins treat props as walls through `gobGround`, and shove one over if held up for long. Suite `dispatch` sends out fire engines, police cars, ambulances and news vans from real stations. - **Vehicle collisions by mass (`vehicles/collide.js`, tuning in `CO`):** two cars that meet (the fender-bender loop in `updateCars`, a cheap distance reject first, then `carsCollide`) are pushed apart by mass (`carMass`: `handOf(kind).mass`, the one source of a vehicle's mass, plus a car held on a forklift's forks, so the two are one body) and swap momentum through one 2D rigid-body impulse (`coImpulse`: bodies `{m,I,x,z,vx,vz,w}`, `I=m*(hx²+hz²)/3`, restitution `CO.e`, friction capped at `mu*j`) at the contact point and normal `boxContact` finds (the sibling of `boxesTouch`: least overlap, or the axis it's closing along fastest). The change goes back as `speed` plus `kv` for traffic or `hvel` for a driven car (`carDv`), and spin as `c.yawV`, decaying by HANDLING's grip (`carSpin`, with tyre smoke and a skid over `CO.smokeYaw`). A traffic car spun past `CO.spinAt` stops steering (`c.spinT`, `c.spinH`) and then finds its way again (`carReroute`); a driven one keeps its steering. Damage is from the impulse (`(dv-dmgV)*dmgK`, times HANDLING's `crush` if a kind has one), once per pair per `CO.cd` (`coLately`). `coAfter` adds the flourishes: a tall narrow vehicle hit hard side-on tips over (`tipR`/`tipV`/`tipFall`, lying on its side `carTip` till it's righted after 9 s), one much heavier striking a light one throws it up over the bonnet, and a light vehicle (bicycle, scooters) hit at speed throws its rider off and cartwheels. Walls are the same impulse with an infinite mass (`carWall`, `carWallPt`), and smashing through one goes by momentum (mass times its real velocity into the wall, `carSmashV`, `carSmash`) rather than speed alone; a car sliding sideways (a drift, a knock) feels for a wall on that side before it moves (`carSlideHit`), since its slide just stops dead at one; a driven car's slide and turning never take a corner or side newly into a wall (`carIntoWall`, `carFootPts`), and a tall one's smash adds a ball from the ground so the wall's bottom row goes too (`carSmash`). `setVeh` and `carSpawn` clear `c.wly` (a Gobway's lean, a wheelie), or a car back from the pool as another kind kept it. A hippo is a body of mass `CO.hippo` (a goblin player `CO.gob`) to a car (`hippoCar`: trampling one, or one running into him, Gus and Gertie alike). The big vehicles go through the same impulse (`bigMass` each one's mass, `bigBody` a `TRAIN_BOXES` piece as a body on its course): `bigCrashes` hurts each of two by how much the knock changed its speed (`bigDmg`), so a ship ramming a boat hardly feels it, and a car against a train, plane, boat or ship is knocked and spun by the big one's mass (`carBig`, from `carsOutOfBig`); both keep to their courses. A wreck sliding on (`wsStep`) knocks a live car aside by it (`wsCars`) rather than stopping dead, and a car's wreck keeps the spin it had (`W.w`, from `yawV`, turning `W.h`). Host only; snapshots already carry the result. Suite `collide`.

- **Online co-op (`net/`, full write-up in `docs/multiplayer.md`):** (the host's smashed blocks go at most `NET_EBUDGET` a snapshot, the rest in the next ones) host-authoritative peer to peer, up to four players (`NET_SEATS`; seats past two made when taken). - **Online chat and voice (`net/net-chat.js`, `net/net-voice.js`):** Enter opens a chat line (`CHAT`, `chatOpen`; while it or a controller's quick list, `chatPad`, is up, `readInputs` zeroes player one's controls); the host cleans, rate-limits and passes on every line (`chatFromGuest`, `chatPost`), shown only through `textContent`. Suite `chat` (pretend microphone and connection: counts that nothing's made with voice off); `tools/ui/chatshot.js` chats between two real tabs.
- **Goblin crowds and vehicles (batched drawing):** street goblins (hostiles, civilians, staff) are never in the scene, and cars keep their boxes on layer `BAT_HIDE`, which no camera draws. Their part objects are still moved, hidden and recoloured as normal; each frame `batDraw` copies every shown box's matrix, colour, emissive and snow (`mat.snowU`, set by `snowCar`) into one `InstancedMesh` per box size and material kind (`BAT`, `batKind`). Plain Lambert or Basic boxes batch; one with a texture, transparency or its own shader is left to draw normally on a car, and isn't drawn at all on a goblin. Make new goblin or vehicle boxes with `boxGeo(w,h,d)` so they share shapes and batch together, and never dispose one. Crowding checks use a grid (`GOB_GRID`, `gobCell`), not every goblin against every other. Every pooled goblin (`addHostile`, `addCiv`, `addCultist`, `addFoe`, an online guest's `netGob`) is made by `makeGoblin(o,x)` (`enemies/goblins.js`: o its `goblinModel` options, x that pool's own fields over the shared ones), so a new field every goblin needs goes there once.
