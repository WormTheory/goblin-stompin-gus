# Goblin Stompin' Gus — notes for Claude

A voxel action game that plays from one self-contained HTML file: **`game/index.html`** (~1.7 MB, ~19,000 lines).
It loads three.js r128 from cdnjs; everything else (world generation, meshing, physics, AI, audio, UI) is inline.
Open the file in a browser to play. The source it's built from is in **`src/`**.

## Source layout
- **Edit `src/`, never `game/index.html`.** `python tools/build.py` joins the source back into `game/index.html`, which stays committed because it's what gets played and published, so commit it along with your change. The test tools rebuild it for themselves. `python tools/build.py --check` says whether it's up to date.
- `src/page.html` is the page and its menus' markup, `src/style.css` the styles, `src/js/` the game script, by topic: `core/` (setup, blocks, audio, the loop, new city, Testing Environment), `world/` (the plan and terrain, `generate.js` has `genChunk`), `buildings/`, `dressing/` (street furniture, props, doors, signs), `render/`, `destruction/`, `player/`, `enemies/`, `vehicles/`, `venues/`, `ui/`.
- **The files in `src/js` aren't separate modules.** They're joined in the order in `src/js/ORDER.txt`, inside one function, so they share one scope: any file can use anything from any other with no imports, and every top-level name must be unique across all of them. No file runs on its own. Order only matters to code that runs while the page loads, such as a `const` read at the top level before the file declaring it. A new file must be added to `ORDER.txt`, or the build stops and says so.
- A topic can be in more than one file, because the code keeps the order it always ran in (`makeCar` is in `vehicles/cars.js`, but `updateCars` is in `vehicles/traffic-update.js`). Search all of `src/js` for a name, rather than guessing the file.
- **Patch notes** live in `src/patch-notes.md`, newest update first (`## ` per update, `### ` per section, `- ` bullets; `build.py` says which bits of Markdown it understands). The build puts them in the menu's Patch notes tab (`#tabNotes`, with the newest update's heading in the title screen's "What's new" line) and builds `game/patch-notes/index.html` from the template `src/patch-notes.html`, which GitHub Pages serves at `/patch-notes/`. Commit that file with `game/index.html`. When a change is worth telling players about, add it to the top update there, or start a new `## ` update, written for players rather than as a commit message.
- **Old versions** are playable from the Patch notes: an older update headed `## Version X` gets a "Play X" link to `<site>/v/X/`, which the Pages workflow builds from the git tag `vX` (`tools/archive_versions.py`, run on every deploy; it warns about a version with no tag). So when a version is released, tag the commit that was pushed (`git tag v0.2 <commit>`) and push the tag with it. Each old copy gets a script that prefixes its localStorage keys with `gsg-vX:`, so old and current saves and settings never mix, and a badge linking back to the latest.
- If `game/index.html` was changed by hand, the build refuses to overwrite it and says how to carry on. `git diff` skips that file, since its changes are already shown in `src/`; `git diff --text` shows it.

## Ground rules
- `game/index.html` is the only deliverable: it must stay one file that works when simply opened. The build only joins files, so keep it that way, with no bundler or dependencies.
- Parody of real brands is welcome and part of the humour (names like "Goblin Walmart"). Draw parody logos rather than copying real artwork.
- Comments are plain English, explaining *why*, often in parentheses. Match the existing style.
- **Bump `SAVE_KEY`** (currently `'goblin-city-v95'`) whenever world generation changes, so old saves don't load into a different world.
- Make edits with exact, unique string replacements. Many identifiers repeat, so check for a single match within the file before replacing.
- After every change: run the tests (below) before calling it done.

## Buildings
Before adding, moving, resizing or changing any building, read `docs/building-standards.md`: what Thomas expects of their scale, placement, look and interiors, the pitfalls, and how to check.

## Running the tests
The game script is pulled out of the HTML and evaluated in Node with a stub THREE and a fake DOM.
That checks logic: world generation, physics, abilities, AI and menus. It doesn't check the real 3D picture.

```bash
bash tools/run_tests.sh                 # smoke, devtest, walk (rebuilds game/index.html and tools/tests/g.js first)
bash tools/run_tests.sh rollt spk lean  # any named suites from tools/tests/
SEED=7 bash tools/run_tests.sh maptest  # Math.random is seeded from SEED
```

The suites only print measurements and never fail on a wrong result, so compare output against the saved baseline:
```bash
bash tools/baseline.sh                  # rewrites tools/baseline/*.txt with timings masked
git diff tools/baseline                 # shows what a change altered; commit it if the change was intended
```

Three audits measure roads, traffic and the coast across a whole world, from generated blocks (slower: run them by hand, from `tools/tests`, with `SEED=1`, `2`, `3` to compare worlds):

node roadaudit.js 9        # motorway dead ends, breaks, and what decks and routes cut through

node shoreaudit.js         # straight cut-offs along block edges, sea bed depth jumps
node streetaudit.js        # trees in streets, block lines through corner bends, unmarked town ramps, barrier jogs at ramp feet
node joinaudit.js 9 30     # drives every lane from the blocks: road missing or blocked, highway ends not joined to streets
node rampaudit.js 45       # Gus walked and sprinted up and down each ramp kind, then every car on a slope: airborne frames, steps, jerk
node themeaudit.js 300     # whether each theme park is whole: all 64 blocks park, the coaster's track, the wheel's legs, the carousel
node sitecount.js 200      # how many of each big site land within that many plots of the middle
node stairaudit.js 160     # which buildings with more than one floor still have no stairs
node signcount.js 150      # how many signs each kind of building carries
node wcaudit.js 150        # which buildings have no bathroom, floor by floor (`wcRooms` places them)
node capaudit.js           # the capitol: every room can be walked to, its doors are really there and drawn, no prop in a wall or doorway
node carride.js            # drop on to moving vehicles: land, ride, no damage

Performance tools: from `tools/tests`, `node toppleperf.js into 0` times every frame of a tall building toppling toward another (`SLOW=14` lists what made slow frames slow), `SPEED=20 node runperf.js 30` the same moving across the world, `node meshhash.js` hashes chunk meshes (compare before and after a mesher change). From `tools/ui` after `build_3d.py`: `node gpuperf.js` gives real frame rates on this machine's graphics card (`VIEW=2000 DETAIL=512` for far settings), `node frameprof.js 12345 idle|run|fall` a browser profile of the real game, `node drawcensus.js` what's being drawn, by kind, `node toppleperf3d.js` frame by frame during a topple with draw calls. From `tools/tests`, `SPEED=35 node spikes.js 45` names the functions behind each slow frame while moving. `relo.js` needs `KIND=` and `MODE=home|move` to be useful (alone it just moves a hospital); `relocmp.sh` does the whole comparison.

To review the chains' logos: `node logosheet.js out.png` from `tools/ui`. To look at a spot in the real game: `python tools/build_3d.py game/index.html tools/ui/t3.html`, then `node tour.js scenes.js outDir [seed]` from `tools/ui` (set `TOUR_VIEW=800` to see that many blocks through the fog, and pass a wait of about 25000 as a fourth argument so distant chunks finish building).

How a test works (see the first ~40 lines of `tools/tests/dead6.js`, which is the standard header):
- **Loading the game.** `mkg.py` rebuilds `game/index.html`, then copies its main `<script>` (the one after the three.js tag) into `g.js`, so `g.js` is all of `src/js` joined up. Each test reads `g.js` and seeds `Math.random`.
- **Reaching internals.** A regex swaps the closing `requestAnimationFrame(frame);\n})();` for `window.__t={...}`, which exposes the functions that test needs. If you add an internal a test must reach, add it to that test's `window.__t={` list.
- **Stubs.** Next come the stub THREE classes (`class Q{` … up to `const listeners=`), a fake `document`, `localStorage` and gamepads.
- **Driving the game.** `eval(src); const T=window.__t;` then `T.frame(now)` advances the game. `run(seconds)` is already defined in the header, so don't redeclare `run`.
- **New test.** Copy the header from `dead6.js`, adjust the `window.__t` export list, then write the checks.

UI tests (Playwright + Chromium) drive the real page with the stub THREE swapped in:
```bash
python3 tools/build_ui.py game/index.html tools/ui/ui.html
cd tools/ui && node uist.js      # also: padnav.js (controller menu nav), uishot*.js (screenshots), uiex.js
```

Map tools (`tools/map/`):
- `topview.js` / `gview.js` render top-down maps of generated terrain to `.ppm`.
- `tv.sh` converts those to PNG.
- `sec.js` / `secz.js` render cross-sections.
- `elev.py` plots elevation.

### Real rendering (local only)
The stub can't show the real picture. To check visuals (`npm install` and `npx playwright install chromium` first):
```bash
python tools/build_3d.py game/index.html tools/ui/t3.html   # local three.js, internals on window.__G
cd tools/ui && node real3d.js [seed] [outDir]               # menu, spawn, above spawn, motorway, country road
```
It renders in software, so the picture is right but the frame rate says nothing about a real graphics card.

## Map of the code (search `src/js` for these names)
- **World and terrain:**
  - chunk generation `genChunk`; meshing (`meshes`, `MESHED`)
  - far LOD rings `farJobNear`/`farJobMid`/`farJobFar` via `farBox`
  - world curve `CURVE_U`, lighting `WORLD_LIGHT`. Any second renderer (e.g. the obituary preview) must zero/whiten these while it renders.
- **Roads:**
  - towns `placeAt`; road spans `axisSpan` (kinds include `'moto'`, `'country'`; `flat` ends)
  - motorway ramps `hwRampAt` / `hwRampCol` / `rampBlocked` / `hwFootNear`; route ends `rtFlat`, `rtRamp`
- **Player:**
  - frame loop `frame`. It substeps when dt > 0.05; presses only count on the first substep, and held state like `inp.chargeHeld` carries across.
  - abilities live in `AB` (toggles), saved under localStorage `goblin-stompin-gus-abilities`
  - bite / stomp / pound with charge levels (`stompCap`, `poundCap`)
  - dash / sprint / air dash; `longJump` (with `LJ_GRACE`); roll; blast dash / blast air dash; blast long jump (`blastOff`, `crushBall`)
  - rocket boost (`ROCKET_*`); ground spike (`groundSpikes`, `spikeGround`, `SPIKES`); climb; crash landing; fall-damage immunity
- **Destruction:**
  - `crush(...)` (accepts `{round:R}` for round craters)
  - building collapse lean is worked out from surviving structural blocks and snapped to a cardinal direction within 20° (`snapCard`)
- **Buttons on screen:** HUD text names a button as `⟦glyph id⟧` (`btnMark`, `bindGlyph`, `actMark`), and `hudHTML` draws it with the menus' `glyph`. Use these for any new prompt rather than `keyLabel`/`padLabel`.
- **Controls:**
  - `ACTS` / `BINDS` (localStorage `goblin-binds-v1`), `KB_RESERVED`, `PAD_RESERVED`
  - `rebindHTML`, `keyLabel`, `padLabel`
  - controller menu navigation `menuNav` (spatial up/down)
- **Abilities menu:** rows `.abil2 > .ab-row`, upgrades in `.ab-up`, toggles use `data-base`, `data-prev`, `data-excl` (roll ⟷ blastDash).
- **Props:** furniture made of small boxes rather than whole blocks, in proportion to the goblins (about 1.4 tall): models in `PROPS`, placed by `hospProps`, drawn by `refreshProps` as instanced boxes near the player, knocked down by `knockProps`. Hospitals are laid out by hand; everywhere else `furnProps` reads what `furnRaw` says stands there, and `furnTurns` decides which of those blocks become props (shelves, fridges, sofas, beds, plants, small tables, lone screens). Restaurants (`restProps`), shops and stores (`shopRoom`), malls (`mallProps`), houses (`homeRoom`), flats (`aptFloor`), workplaces (`workRoom`) , public buildings (`civicRoom`) and venues and workplaces such as cinemas and factories (`venueRoom`) are laid out by hand from a shared set of models. Pavement and park benches and litter bins are props too (`streetFurn`, drawn by `refreshProps` out to 96 blocks rather than 34, and listed in `activeFix` so traffic hits them); taller street objects are fixtures (`drawFix`). Goblins treat props as walls through `gobGround`, and shove one over if held up for long. Suite `dispatch` sends out fire engines, police cars, ambulances and news vans from real stations. News crews (`reportNews`, `newsAI`) cover fires, car crashes and killings; suite `newscrew` checks each. Suite `proptest` chases a goblin across rooms; `tools/ui/proptime.js` times the props. Outdoor sites are dressed by `siteProps`, drawn by the same street loop out to 96 blocks: the plot types in `SITE_PROPS` (farmer's markets, camps, campsites, the cult, building sites, nurseries, trailer parks, cemeteries, mines, quarries, lumber camps, preppers, militia, thieves, ruins, dumps, parks, plazas, courts, lighthouses, houses), the big sites in `SITE_SUPER` (power stations, zoos, theme parks, stadiums, car parks, big parks), and bunkers and wrecked cars out on the plains (`siteKind` says which a block is; the newer ones are laid out in `SITE_FN`, bunkers' rooms in `bunkerProps`); suite `propaudit` counts props per kind of structure, so the bare ones show up. Campfires (`campFires`) are real fires in `hearths` (`hearthBurn`): they don't spread, burn out, call fire engines or put out in the rain, and only hurt someone standing right on the wood. Campsite motorhomes (vehicle `rv`) are a pool of their own (`RVS`, `manageRVs`), parked on their pitches out of sight, and can be wrecked like any parked car. Suite `campfire` checks the fire's reach, goblins and cultists by it, and the motorhomes.
- **Stairs:** `autoStair` gives any building with a real upper storey a flight, if it fits. A building with `b.stair` gets a railed flight per storey (`stairAt`) of stair blocks (`stairId`: a ramp underfoot, drawn as steps), and goblins chase a hippo between floors with `stairPoint`/`onStair`. Fire stations and schools so far; suite `stairs` tests going up and down. A very long building can have a second flight in `b.stair2` (read through `stair2Of`; so far just the university library).
- **Goblin routes:** `navUpdate` keeps one map per hippo, built backwards from where it stands a little each frame (`navExpand`; `navCol` lists where a goblin can be in a column of blocks), and `navSteer` reads it: walk, hop, running jump, climb up or down a wall (`gobStartMove`, `gobMoveStep`), with swimming handled where gravity is. `stairPoint`/`roomStep` are only the fallback now. Suite `chase` times goblins running a hippo down in every big building, up cliffs and across water, and counts their blows on a hippo stood on vehicles; `tools/ui/chasecost.js` times the maps in a real browser with a full crowd.
- **Placement:** `SITE_F` says how far out from a place's middle each kind of site goes (`siteFits`); a dump is a 4x4 `dumpSite` at the end of a street.
- **Roofs:** `roofOf` picks a shape per kind of shop (hip, mansard, gable, barrel, false front, dome, mirror ball), drawn by `roofColumn` above the flat roof.
- **Trains:** one per track (`updateTrains`), an engine at each end; `T.s` is the front, but the cars are numbered from the far end of the line, so they keep their places when it reverses. `trainHit` damages one car; losing one halts the train. Riders are carried round bends in the car's own frame. Suite `trainride` tests all that.
- **Airplanes:** `updateAirport` flies one and parks two; `planeBoxes` gives each a fuselage and wing box in `TRAIN_BOXES`, so they're stood on and hit through the same code as trains (`trainHit` passes them to `planeHit`). `planeWreck` handles the fall and the replacement.
- **Theme park rides:** a venue (`makeRides`, `updateRides`), whose parts are stand-ins in `TRAIN_BOXES`, so they're hit through `trainHit` (passed on to `rideHit`) and stood on like trains. The coaster stops if a car's destroyed and derails if its track is broken, the wheel falls if its A-frame loses a side (`wheelFall`), the carousel goes if its floor does. `themeOf` alone decides whether a park goes in, and only where all 8 x 8 blocks are free (moved up to two blocks along to find room); `themeBusy` stops answers worked out meanwhile being cached. `rideSurvey` still leaves out a ride with nothing under it, and only blocks in `edits` count as broken (`rideBroke`).
- **Zoo animals:** `animalBox` gives each a soft box in `TRAIN_BOXES` (hit, but not stood on or bumped into), `animalHit` hurts them through `trainHit`, `ANIMALS` has their health and score. Dead animals and wrecked rides are kept in `wrecked`, saved with the world.
- **Boats:** everything afloat is a box model made by `makeBoat` (kinds in `BOATS`), baked into one mesh, and moved by `updateBoat`: on rounds at sea along a racetrack route that stays on open water (`boatAt`, `boatLane`, `lanePt`), or tied up where `mooredBoats` says (harbours, port and naval quays, a dry dock, off a beach, on the sand, at a rig). `boatBoxes` puts them in `TRAIN_BOXES`, so they're stood on and hit through the same code as trains; `trainHit` passes them to `boatHit`, and `boatWreck` handles the sinking and the replacement. Jump while swimming beside one to climb aboard (`boatBeside`). Suite `boatride` tests all that. Wrecks on the sea bed are still blocks (`wreckBlock`).
- **Climbing vehicles:** vehicles aren't blocks, so spider-climbing one is its own hold, `p.vcl` (only while `p.state` is `'climb'`): a face of the vehicle's box (`vBox`: a car's, or one `TRAIN_BOXES` piece of a train, boat or plane) and a spot on it in the vehicle's own frame, so he goes wherever it goes. `vGrab` takes hold (walking or jumping into one with climb held, or one that would have run him down), `vClimb` moves him on it (round corners, up on to the top, down off the bottom), `vOverEdge` tips him off a roof on to the side, and `vRepin` puts him back on his hold after the vehicles have moved each step. Suite `vclimbt`.
- **Crashes between vehicles:** cars bump each other (`updateCars`), trains and planes smash cars and goblins in their way (`trainBoxes`, `planeStrike`), boats run goblins down (`boatStrike`), any car over 5 a second runs a goblin down, and `bigCrashes` knocks two big vehicles (train, boat, plane) that meet, once each time they meet. Suite `vcrash`. Solid against each other: `MIL_PARTS` are a tank's and a helicopter's solid boxes (a helicopter's tail boom too), used by `milBlocked` and `milBoxes`; `carsOutOfBig` keeps cars out of every other big vehicle, `milOut` pushes a tank or helicopter back out of a train, plane or boat that's come through it, both by `outOf` (the shortest way out, allowing for which way the box faces); a driven plane or boat stops at, or at speed crashes into, any vehicle in the way (`vehIn`, `vehHurt`). Suite `vcollide`.
- **Cultists:** an enemy type, robed and hooded goblins from their own pool (`addCultist`, made as needed by `freeCultist`, flagged `g.cultist`, never spawned into town or counted against the street's goblins). A cult altar's venue (`updateCultVenue`) keeps its circle of them alive while Gus is within 70 (`cultSpawn`, bound by `g.homeV`), shuffling round the altar (`cultCalm`). Coming within 15 of the altar, or hurting one, rouses the cult (`cultRouse`); then they hunt like goblins, but stop to conjure a fireball when they can see him from 4.5 to 30 off (`cultCast`, `cultSees`; the fireballs are `FIREB`, `updateFireballs`, 2 damage) and stab with a ritual dagger up close (1 damage, every 0.85 s). Killed ones stay dead until the cult's had two quiet minutes. The Testing Environment's Cultist button spawns them with no altar, hostile at once. Suite `cult`; `tools/ui/cultshot.js` takes real screenshots.
- **Compound guards:** thieves' hideouts, prepper bunkers and militia camps keep their people as live goblins (`FIG_STYLE`, `FOES`; pool flagged `g.special` like cultists, made by `freeFoe`, placed by `foeSpawn` at the site's posts, towers hold their post via `g.hold`). They mill about (`guardCalm`) until Gus comes close (rouse distance in `FIG_STYLE`) or hurts one (`siteRouse`). Thieves stab with daggers; preppers and militia shoot rifles (`foeRanged`/`foeShoot`, hitscan with a tracer, hit chance falls with distance) and lob grenades (`foeThrow` into `SHOTS`, `updateShots`, bursting via `foeBoom`). Testing Environment buttons Thief, Prepper, Militia.
- **Military base armour:** each base gets an `army` venue (`armyVenue`) whose parked tanks and helicopters are real vehicles with `TRAIN_BOXES` stand-ins (`isMil`, hit through `milHit`). Entering the base rectangle or hitting one alerts it (`milAlert`): up to `MIL_ROLL` tanks hunt at once (`updateTank`: turret tracks, drives, fires shells) and the helicopters lift off, circle and strafe with bursts and rockets (`updateHeli`). Destroyed ones are saved as wrecked; the base stands down 30 s after Gus leaves. They're solid: `milBlocked` stops a tank or helicopter moving into another base vehicle or a train, plane, boat or ride car (a blocked tank swings aside for a moment, `M.detour`), and `milShove` pushes goblins and cars out of their boxes, a moving tank running goblins down and ramming cars. Suite `site`; `tools/ui/siteshot.js` takes real screenshots.
- **Crews (`vehicles/crews.js`):** a base's tanks and helicopters and a militia camp's vehicles start empty. A real base's `M.crew` is null until a soldier reaches it: `updateArmy` picks a vehicle as before, `milCall` sends a soldier (`crewSend`, out of the `FOES.soldier` pool) from the barracks fronts, and the vehicle waits in state `'man'` (`milManning`) till he's in, or goes back to `'park'` for a few seconds (`M.callT`) if he's killed. Back in its place after standing down, the crew climbs out and walks to the barracks (`milDismount`). The Testing Environment's tanks and helicopters come crewed (`MIL_CREW`). A goblin running for a seat carries `g.mount` (`{o,seat}`, or `{home}` going back), and `updateGoblins` runs `crewRun` in place of its usual round. On arrival, or if it's despawned out of sight, `crewBoard` puts it in the seat (its `g.id` becomes the seat's) and returns it to the pool. The militia's vehicles are `VEH.technical` (a pickup with a machine gun on a post, its gunner turning with it, `vehG.technical.gun`/`.gunner`) and `VEH.quad` (a rider, `rider`, and a rifleman behind, `gun`/`gunner`), never in traffic, from their own car pool (`CREWCARS`, `c.crewPool`). Each has `c.crew` (`{k,drv,gun,go,...}`, identities in the seats; `crewShow` shows who's aboard). The guards' venue keeps them at `CREW_SPOTS` (`crewSite`): put out while you're near, crewed by militiamen from the HQ (one runner a seat) once roused, gone while wrecked till the camp's quiet two minutes are up, removed with the venue (`crewDrop`). `updateCars` runs `crewDrive` for a crewed one (circling the nearest player at its own distance, steering off other vehicles) and `crewGun` fires its gun (`CREW_GUN`). Wrecked, `crewWreck` throws out their bodies (`crewCorpse`). Carjacked, the driver comes out fighting and the gunner jumps off (`crewBail`). The Testing Environment's Technical and Quad buttons use `tenvCrew` (hunting: crewed; parked: empty). Suite `crews`; `tools/ui/crewshot.js` takes real screenshots.
- **Characters (title screen's character select, `ui/char-select.js`):** Gus, Gertie or Gnash the goblin, kept under localStorage `goblin-stompin-gus-character` (`CHAR`, `setChar`). **Gus and Gertie must stay mechanically identical** (Thomas's standing rule): anything that changes what Gus can do must apply to Gertie too. A player's seat is `p.idx` (player one or two: input, split screen); which hippo they are is `p.who` (0 Gus, 1 Gertie), and that's only looks and voice (`dressHippo`, `charName`, `charTint`): never branch a move, size or ability on either. Picking Gertie makes player one Gertie and player two Gus. Suite `twins` plays both through the same moves on the same inputs, frame for frame, as hippos either way round and as goblins; every line should say `furthest apart 0.000`. `tools/ui/charshot.js` screenshots the cards and checks picking them by mouse and arrow keys.
- **Play as a goblin (Gnash):** goblin mode is each player's own (`p.gob`, set by `setGobP`; `setGob(on,p2)` sets both, player two the other way if `p2` is given; `DT.gob` only says whether anyone is a goblin), so co-op can be a hippo and a goblin. Player two's kind is the title screen's "Co-op, player two" row (`CHAR2`, localStorage `goblin-stompin-gus-character2`; unpicked, the same kind as player one). One goblin is Gnash whichever seat; two, and player two is his cousin Grizzle (`GOB_NAMES`, `charName`). Anything about one player's body or moves asks that player (`p.gob`, `bodyOf(p)` for the box, `ptsOf(p)` for the feet, `camPitch(v,p)`), never a game-wide switch. Suite `mixcoop` plays Gus and Gnash side by side; `tools/ui/mixshot.js` takes real screenshots. `setGobP` swaps the player's body sizes, and `updatePlayer` runs the normal player code (`movePlayer`) with `GOB_ABIL` and goblin speeds in place of `ABIL` for that step. `gobCamera` is the first-person view, `gobKit` the goblin others see and your own arm and club, and hostility works just as it does for Gus. Clinging to a wall his feet are 0.06 off its face (a hippo's spot), inside the near plane, so `eyeRoom` keeps the eye `GOB_EYE_R` clear of every block (and his body comes off the wall with it), and `pivArc` swings the eye round the edge going round a corner or between a wall and a ceiling; the climbing lines of suite `gobmode` measure both, and `tools/ui/gobclimb.js` takes real screenshots on a wall. Suite `gobmode` checks it against a hippo; `tools/ui/gobshot.js` takes real screenshots.
- **Gnash's weapons (`player/gob-weapons.js`):** `GOB_ABIL.dash` gives him the dash (with no direction held it goes the way he's looking). He carries `p.wpns` (club, dagger, rifle; `GOB_WPN`, in hand `p.wpn`, `gobArms` sets it up, `setGob` clears it) and `p.gren` grenades (up to `GREN_MAX`). `doBite` calls `gobAttack` for the weapon in hand (the rifle is `gobShoot`, a hitscan ray from the eye), stomp throws a grenade (`gobThrow`, from `gobArmsTick`) and the `weapon` action (R, pad d-pad right) goes to the next (`gobNextWpn`). A goblin killed by a player goblin (`GOB_CAUSES`, in `damageGoblin`) drops its gear (`gobGear`, `gobDrop`): its weapon if a player hasn't got it, grenades always; `gobPickups` spins them and picks them up. `gobArmsHud` is the weapon bar and the rifle's crosshair; `gobCamera` shows the held weapon, in your own view (`gb.held`) and on the goblin the others see (`gb.tp`, the rifle raised to where you look). `bindHint` gives Gnash's own controls (`gobHint`). Pipe bombs are gone: preppers throw grenades. Suite `gobarms`; `tools/ui/gobarms.js` takes real screenshots of the weapons and the bar.
- **Driving (as Gnash):** the `use` action (F, pad Y; in `ACTS`, read as `p.in.use`) gets into the vehicle nearest you (`drvFind`: a car, or a `TRAIN_BOXES` piece of a train, boat, plane or base vehicle) and out again (`drvEnter`/`drvExit`). `p.drv` is what you're in, and the vehicle's `.drv` its driver; each vehicle's own update reads the driver's controls in place of its round (`drvCar` in `updateCars`, `drvTrain`, `drvBoat`, `drvPlane` in `updateAirport`, `drvTank`, `drvHeli`), and `drvSeat` puts you in your seat after everything has moved. W/S throttle, A/D steer; helicopters fly the way you push relative to the view, Jump climbs and Climb (or Dash) drops; a plane flies on a simple flight model (`drvPlane`: W/S set a throttle that stays put, A/D bank it and a banked plane turns, Jump pulls the nose up and Climb pushes it down; lift from airspeed and the wing's angle to the flight path, `PLANE_KL`, climbing costs speed and diving gains it, past `PLANE_AOA` or too slow it stalls, `planeStalled`; let go it eases back to level; it rotates and lifts off past about `PLANE_LIFT`; touching down too fast or on a wingtip wrecks it; the gauges are `planeHud`, and an airport is kept, `drvHeld`, while a plane flown off it is still going); bite fires a tank's shell, or holds a helicopter's machine gun (`heliGun`), and stomp (right click, RT) fires a helicopter's rocket, where you look (`drvAim`); otherwise bite sounds the horn. Tank and helicopter weapons have magazines and reload times (`DRV_WPN`, `wpnInit`/`wpnTick`/`wpnFire` on `o.wpn`), shown by the ammo panel just above your hearts (`drvHud`: the vehicle's health box and `.dammo` sit in `.dveh` inside the player's `.bar`); firing with nothing loaded clicks (`wpnClick`). Getting into a vehicle with someone at the controls (`jackable`: a car's `driver` with its head showing, a tank or helicopter not left `'idle'`) plays a carjacking first (`carjack.js`: `D.jack`, ticked in `drvTick` by `jackTick`, posed in `drvSeat` by `jackPose`, with a stand-in goblin for you, `p.jackA`, and a door, hatch lid or sliding door made for it, `jackDoor`); the driver comes out of the goblin pools (`jackVictim`: a soldier, `FOES.soldier`, out of a tank or helicopter; a hostile goblin in police blue out of a police car; otherwise the driver, as a civilian who runs, `jackFear` in `civAI`, or now and then a hostile one who fights, `jackGrudge` in `updateGoblins`, even in goblin mode). A driven fire engine's bite holds a water cannon instead (`hose.js`: `drvHose` from `drvCar`, the stream in `c.hose`, `hoseHit` every `HOSE_TICK`): it douses `fires` it reaches and pushes goblins (`kv`, a short `stun`) and cars (`kv`, less for big ones) along the stream without hurting anything; stomp is its horn. On a motorcycle your own goblin is drawn sat on it (`rideShown`/`ridePose`; in anything else you're out of sight, see `gobView`). A driven tank pushing into blocks taller than a step knocks out a hole the size of its front (`tankRam`), going straight through at speed. The view is a chase camera (`drvCamera`). You can't be hurt while driving; a wrecked vehicle throws you out. Left behind: a car stays where it stopped (`c.left`), a tank or helicopter goes `'idle'` (a helicopter settles to the ground), a plane flies on and comes down by itself, a boat stays off its route; a venue holding a driven vehicle isn't dropped (`drvHeld`). Suite `drive`; `tools/ui/driveshot.js` takes real screenshots.
- **Vehicles in a fight:** shells and rockets carry `vd` (damage to vehicles) and `own` (the vehicle that fired, spared); they go off on a vehicle they meet (`shotHitsVeh`), and every blast (`foeBoom`) also harms the vehicles round it through `vehBlast`. A vehicle hit shows it (`vHitFx`; a base vehicle jolts), and a badly hurt one smokes, then burns (`vDamaged`). Aircraft coming down hard go up in an `airCrash` (a crater, a fireball, fire): `planeCrash`, a shot-down helicopter landing, a driven helicopter flown into something at speed. Stopped helicopters and wrecks drop when the ground under them is blown away. While driving, `drvHud` shows the vehicle's name and health, and for a tank or helicopter a crosshair (dim while reloading, red when locked) plus a marker (`.xt`) at where the shot would really go off if fired now (`shotPath` flies it as `updateShots` would: the tank gun's elevation limits and turret lag (`tankShell`), anything in the way; faint when it never comes down on anything, orange at the screen edge when off it). A tank's or helicopter's chase camera sits higher and further back than other vehicles'. Lock on (Q / R3) takes tanks and helicopters too (`isMilT`, `lockY`); from a tank or helicopter it picks what's nearest the crosshair out to 100 blocks (`drvLock`) and the gun aims at it, led (`drvLead`), while the camera stays free. A car being driven (or hunting) jolts up a one-block step (`c.stepT` holds its back wheels up till they're over the lip, in `carPhysics`). Motorcycles (`VEH.bike`) are part of the traffic mix and lean into their turns. A driven or hunting car that hits a wall above 13 a second smashes a hole in it (`crushBall`, sized by speed and vehicle), takes a big knock and carries on through, slowed; slower, it bounces off. A driven tank rammed into anything more than a block high at speed goes straight through it.
- **Toppling (`destruction/topple.js`):** a falling piece is rigid, so its blocks are shared out among cuboid sections (`toppleSections`), and a section whose box is clear of everything (`boxClear`, from `tileTopsOf`: the top block of each 4 x 4 of columns, kept on the chunk's array) is passed over in one go. Only sections touching something look block by block. Goblins and cars are tested by turning them into the piece's own frame (`within`, `T.bset`).
- **Chunk rebuilds:** `rebuildSet` only queues; `flushRebuilds` does them at the end of the frame, a few milliseconds' worth, oldest first. The blocks change at once, the picture can lag a frame or two. Use `buildChunk` directly only when it must be now. `buildChunk` keeps its working buffers between chunks (`MB`, `MBuf`) and must keep producing the same geometry: `tools/tests/meshhash.js` hashes it.
- **Dust, smoke, rubble, blood:** `parts`, `rubble` and `decals` are plain objects, not in the scene; `fxDraw` copies the live ones into one instanced mesh per kind (`PART_M`, `RUBBLE_M`, `DECAL_M`). `fxSent(M,n)` sends only the n boxes in use to the graphics card: use it for any instanced mesh rebuilt often.
- **Batched models:** besides goblins and cars, `batDraw` batches the signal heads, doors, landmarks and venue models listed by `decoEach`, into batches flagged `deco` that the Structures preview also draws. A box of any size goes into one batch per material kind, as a unit box scaled to size, if its geometry is tagged `.ub=[w,h,d]` (`boxGeo` does this). The scene's own `updateMatrixWorld` skips hidden top-level objects and anything batDraw has just done (`wmFrame`, `wmDone`). `warmShaders` compiles every program on the second frame, so nothing compiles during play: a material of a new kind made lazily should be added to it.
- **Not stalling the frame:** don't call `get` on places that may not be loaded from per-frame code (it makes the chunk, a couple of milliseconds each); check `chunks.has` first, as `updateFlecks`, `holeOn` and `fixCanAsk` do. `plotType1` is remembered per plot (`plotTypeC`, cleared with `plotCache`).
- **Far chunks in groups:** `regionTick` copies up to 4 x 4 chunks a little way off that have settled into one mesh per material (`regionMerge`, `REGIONS`) and hides the chunks themselves, which cuts draw calls a lot at long detail distances. `buildChunk` and unloading call `regionTouch`, which puts the separate chunks back. `tools/ui/regioncmp.js` checks the picture is unchanged, pixel by pixel.
- **Saves:** smashed blocks go in the save packed chunk by chunk (`ed2`, `editsPacked`, `editsUnpack`), about 3 characters each, with each chunk's string reused until it changes; old saves with `edits` still load. A full browser store now says so on screen. `tools/ui/savetest.js` round-trips both forms.
- **Stalls when arriving somewhere new:** `planAhead` asks a place's street questions a little each frame before `setConns` needs them, and `mayLook` allows anything that isn't the chunk loader one new chunk a frame. Plumes thin out if frames run long (`frameMs`, in `updateFires`).
- **Enemy hostility:** a three-step setting, `DT.host` (0 Passive, 1 Peaceful, 2 Normal; saved under `HOST_KEY`), set from the main screen's slider (`hostMain`), the Options tab's (`hostility`) and the quick menu's `host` row, all kept in step by `syncHost` (which also sets the main screen's description, `HOST_TXT`, to the step chosen). `calmNow()` (below Normal) is what stops goblins, cars, police, soldiers and roused sites going after you: hostile goblins act like the townsfolk instead (`civAI`), who still run. `passiveNow()` (Passive) also stops anyone running from you in `civAI`, and a hit no longer puts a news crew, medic or firefighter off their job, though they're hurt and killed as normal.
- **Debug menu:** the quick menu's rows and sections are in `DBG_SECS` (column, title, rows). It's the only home of the debug switches (Game options keeps just the one allowing it, which also shows the Dev tab); its Show / hide tab (`DT.tab`) keeps the rows hidden from the first tab in `DBG_HIDE`. Its Rendering switches only change the picture: props by hiding `PROP_L`/`PROP_G`, fixtures by hiding `FIX_BAR`/`FIX_GLOW`/`FIX_COL` and the sign, signal and billboard groups, and caves, sewers and subways by drawing each chunk from `gfxArr`, a copy with what `gfxRec` says those features wrote filled back in with earth. Its Interface switches (`UI_PARTS`: a CSS selector per part of the display, hidden through one style sheet) add a row and an Options box each from that table. None of these are saved. The Sound list overlay (`sndNote`, drawn by `sndTick`) names each sound from `sfx(name,...)` around it, or else from the function that made it (`SND_FN` puts those into words); a new sound worth telling apart from its neighbours wants an `sfx` round it. Suite `gfxhide` checks them and the menu's navigation.
- **Dev tab:** `DEV_ABIL`, `DEV_SCRIPT`, sandbox `SBX`, Structures previewer (`ST`, `stBuildList` — built lazily because `TEST_GROUPS` is defined later).
  The moves preview has a character picker (`DEVP.char`, `devSetChar`, kept in this browser): Gus and Gertie run the same recording (`devSimulate(key,ch)` only dresses the spare hippo differently), Gnash runs the moves in `DEV_GNASH` as a goblin (`DT.gob` on, `gobDims`, `gobMove`) and is drawn on a goblin model posed by `gobBodyPose`, the same pose the others see in co-op. Each model is a figure (`devFig`: its parts, recorded frame by frame, and its rig) in `DEVP.figs`. Gnash's moves have no settings or custom hitboxes here: his pane is frame data (`devRenderGnash`).
  The Enemies section (`ui/dev-foes.js`, `DEVF`) plays each kind in `DEV_FOE_KINDS` through each animation in `DEV_FOE_ANIM` (`devFoSim` records it). It doesn't run the real AI: each step repeats the sums the enemy code does (the chase in `enemies/routes.js`, `civAI`, `cultCalm`/`cultCast`, `guardCalm`/`foeRanged`, `gobMoveStep`), and reads its numbers from `FOES`, `CULT_CAST` and `FB_SPEED`. So a new table value shows up by itself, but a change to one of those poses or timings wants the same change in `DEV_FOE_ANIM`, and a new enemy kind an entry in `DEV_FOE_KINDS`. Suite `devtest` records every kind and animation.
  The previewer meshes the structure's blocks itself (`stMeshes`), but its dressing (lamps, signals, signs, benches and bins, props inside, doors, shop signs, landmarks, rides, animals, boats) is the game's own: `viewers()` adds stand-ins spread over the box (`ST.view`, `stViewers`) to the players every refresh loop goes round, `stDress` runs those refreshes, and `stDrawDeco` draws just that dressing from the game's scene (`stDecoSet`), cut to the box with clipping planes. So a new kind of dressing shows up there by itself if its refresh loops over `viewers()` and its models are in `stDecoSet`. Fly mode (`stFlySet`, `ST.fly`) is a noclip camera whose position is one more viewer, so furniture loads round it floor by floor.
- **Testing Environment (title screen):** an empty, flat world (`TENV`, saved with the world; null in a normal city). Only the plan's blocks inside spawned boxes (`TENV.boxes`, in plots; `tenvShow(px,pz)`) are generated (`genChunk` returns `flatChunk` elsewhere) or dressed: every refresh that loops over plots near `viewers()` skips the rest, and traffic, crowds, services, trains and pull-overs don't spawn at all. Spawning a structure searches the plan ring by ring with the Structures previewer's `stMatch` (`tenvTick`), and builds it on the nearest clear ground in front of Gus (`tenvSpot`, `tenvPlace`, `tenvRebuild`): a box keeps where it came from in the plan (`sx,sz`) and where it's built (`ax,az`; an old save without `sx` stays put). Inside a moved box and the ring of plots round it, the plan's lookups answer as at the source with their positions moved across (`trInstall` wraps them, only in the Testing Environment; only the outermost call is moved, `TR.d`; moved copies kept per box in `TR.c`), and its chunks are the source's own, made raw (`trChunk`, with `collapses` keys translated). A new plan lookup that dressing calls with a place needs adding to `trInstall` too: `tools/tests/relocmp.sh` (or `relo.js` per kind and `relocmp.js`) builds each kind in place and moved and compares blocks, meshes, props, doors, signs and staff. Its panel (`#testPanel`) is its own menu tab, `tabTest`, right of Game: `tpShow` shows its button only while `TENV` is set, and `showTab` passes over any tab whose button is hidden. Enemies come from `tenvFoe`, cars from `tenvVeh`, tanks and helicopters from `tenvMil` (a base of their own, the `tenvArmy` venue), parked planes from `tenvPlane` (an airport of their own, the `tenvPlanes` venue, flagged `tenv` so `updateTenvPlanes` runs instead of the timetable); Reset world (`tenvReset`) starts a fresh empty one. Entering parks your city under `goblin-stompin-gus-city-parked` and leaving restores it (`tenvEnter`/`tenvLeave`). A new kind of dressing or spawner that loops over plots needs a `tenvShow` check too. Suite `tenv` checks it; `tools/ui/tenvshot.js` takes real screenshots.
- **Online co-op (`net/`, full write-up in `docs/multiplayer.md`):** host-authoritative peer to peer, up to four players (`NET_SEATS`; seats past two made when taken). The host runs the game with a guest's seat driven by its controls (`p.net`, `netHostInputs`); a guest builds the host's world from its save (kept in sessionStorage, `netWorldText` in `load()`, then a reload), sends its controls (`netSendInput`) and draws snapshots (`netSendSnap`/`netCommit`/`netGuestFrame`) `NET_DELAY` behind, with the host's goblins and cars as mirrors in `NETM` and venue joints pinned (`netVenues`). Effects reach a guest by wrapping the functions that make them (`netFx`), blocks through `addEdit`; on a guest, damage, `crush`, `setRaw` and `addEdit` do nothing unless the host sent them (`NET_APPLY`). A guest moves its own hippo at once (`NETP`, `netPredStep`) and is eased back (`netPredCheck`); the host rewinds goblins for a guest's attacks (`netRewind`). Transports: Trystero (`NET_TRYSTERO`, loaded on use; TURN hook `NET_TURN`), a BroadcastChannel for two tabs (`netLoopback`), the tests' own via `NET.makeTr`. `netOn()`/`netHost()`/`netGuest()` say what's going on; offline none of it runs. A new effect function worth seeing on a guest wants wrapping with `netFx`; a new thing that changes blocks should go through `addEdit`. Suite `net`; `tools/ui/netshot.js` two real tabs (`P2P=1` through the internet).
- **Goblin crowds and vehicles (batched drawing):** street goblins (hostiles, civilians, staff) are never in the scene, and cars keep their boxes on layer `BAT_HIDE`, which no camera draws. Their part objects are still moved, hidden and recoloured as normal; each frame `batDraw` copies every shown box's matrix, colour, emissive and snow (`mat.snowU`, set by `snowCar`) into one `InstancedMesh` per box size and material kind (`BAT`, `batKind`). Plain Lambert or Basic boxes batch; one with a texture, transparency or its own shader is left to draw normally on a car, and isn't drawn at all on a goblin. Make new goblin or vehicle boxes with `boxGeo(w,h,d)` so they share shapes and batch together, and never dispose one. Crowding checks use a grid (`GOB_GRID`, `gobCell`), not every goblin against every other.
